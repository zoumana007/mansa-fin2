# 89 — Publicité, Sponsoring et Mise en Avant Mansa : campagnes, ciblage, emplacements, enchères, budgets, mesure, anti-fraude, conformité, administration et reporting

## 1. Objet du document

Ce document définit le cahier des charges complet du système de **Publicité et Sponsoring Mansa**.

Le système doit permettre à des acteurs autorisés de promouvoir :

- un commerce ;
- un produit ;
- un service ;
- une promotion ;
- une réservation ;
- une application ;
- une campagne institutionnelle ;
- une offre partenaire ;
- un événement ;
- un contenu éducatif ;
- une fonctionnalité Mansa ;
- une initiative publique autorisée.

La publicité doit rester intégrée à l’écosystème Mansa sans nuire à la confiance, à la sécurité, à la confidentialité ni à la lisibilité des applications.

Les contenus payants doivent toujours être clairement identifiés comme :

- Sponsorisé ;
- Publicité ;
- Partenaire ;
- Mise en avant payante ;
- Promotion commerciale.

---

## 2. Principe général

Le parcours général doit être :

```text
Création de campagne
→ Choix de l’objectif
→ Sélection de l’audience
→ Choix des emplacements
→ Définition du budget
→ Import ou création du contenu
→ Vérification automatique
→ Validation éventuelle
→ Diffusion
→ Mesure des résultats
→ Facturation ou consommation du budget
→ Audit
```

Aucune campagne ne doit être diffusée sans :

- annonceur identifié ;
- budget valide ;
- contenu conforme ;
- période définie ;
- audience autorisée ;
- règles de confidentialité respectées ;
- statut actif ;
- validation lorsque nécessaire.

- bloquer une opération financière ;
- masquer un solde ;

- ralentir un paiement ;
- imiter une alerte de sécurité ;
- imiter une notification système ;
- contenir de faux boutons ;
- provoquer des clics involontaires.

## 29. Mode enchères

Le système peut proposer un mécanisme d’enchères pour certains emplacements.

Types possibles :

```text
CPC
CPM
CPA
CPL
CPV
FIXED_PRICE
HYBRID
```

Avec :

- CPC : coût par clic ;
- CPM : coût pour mille impressions ;
- CPA : coût par action ;
- CPL : coût par prospect ;
- CPV : coût par vue ;
- prix fixe ;

---

## 30. Limites des enchères

Le plus offrant ne doit pas automatiquement gagner si :

- le contenu est peu pertinent ;
- l’annonceur est à risque ;
- le produit est interdit ;
- la destination est trompeuse ;
- l’expérience utilisateur est mauvaise ;
- la campagne dépasse la fréquence autorisée.

## 104. Règles métier

1. Toute publicité doit afficher une mention de sponsoring.
2. Aucun contenu publicitaire ne doit imiter une alerte de sécurité.
3. Une campagne doit appartenir à un annonceur identifié.
4. Une campagne doit avoir un budget valide.
5. Les contenus doivent être vérifiés avant diffusion.
6. Le ciblage doit respecter le consentement.
7. Les données sensibles ne doivent pas être utilisées pour le ciblage.
8. Les mineurs doivent recevoir une protection renforcée.
9. Un utilisateur peut désactiver la personnalisation.
10. Les résultats sponsorisés doivent rester distincts des résultats organiques.
11. Les campagnes sans stock doivent être limitées ou arrêtées.
12. Les clics invalides ne doivent pas être facturés.
13. Les conversions annulées peuvent être exclues.
14. Les dépenses Wallet doivent passer par le Ledger.
15. Les remboursements doivent utiliser une nouvelle écriture.
16. Les budgets doivent arrêter automatiquement la campagne.
17. Les campagnes sensibles doivent être approuvées.
18. Les contenus interdits doivent être bloqués.
19. Les produits réglementés nécessitent les autorisations requises.
20. Les fréquences doivent être plafonnées.
21. Les campagnes peuvent être suspendues immédiatement en cas de risque.
22. Les annonceurs doivent pouvoir contester une décision.
23. Les audiences doivent être minimisées.
24. Les rapports doivent rester agrégés.
25. Les segments trop petits doivent être masqués.
26. L’IA ne doit pas publier sans validation.
27. Les modifications critiques doivent être auditées.
28. Les feature flags doivent permettre de désactiver un format.
29. Chaque pays peut avoir ses propres règles publicitaires.
30. Les audits critiques doivent être immuables.
